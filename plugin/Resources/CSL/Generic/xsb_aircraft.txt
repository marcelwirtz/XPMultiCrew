# XPMultiCrew's bundled generic CSL package (see docs/plan.md section 5 and
# the "generic CSL now, richer packages optional later" decision).
#
# A single hand-built placeholder model (fuselage/wing/tail boxes, flat
# orange-red texture - see generic.obj/generic.png) used for every remote
# aircraft, regardless of its real ICAO type, so Formation mode works with
# zero manual setup. Format per the OBJ8 CSL spec used by XPMP2/libxplanemp.

EXPORT_NAME XPMultiCrew_Generic

OBJ8_AIRCRAFT Generic

OBJ8 SOLID YES XPMultiCrew_Generic/generic.obj

# Without this, XPMP2 falls back to auto-computing the vertical offset from
# generic.obj's own Y extents (CSLModels.cpp's FetchVertOfsFromObjFile) -
# and that auto-detect is a bad fit for this particular mesh: generic.obj's
# vertices all sit ABOVE Y=0 (0.05 to 1.45, no landing-gear geometry below
# the fuselage box), which trips the "min >= 0" fallback branch and returns
# just -1.45 (the negated top of the mesh) as the offset, not anything
# related to where the model should actually sit relative to the ground.
# Result (confirmed live, two-instance test 2026-09-20): remote aircraft
# floated ~1m above the ground, since X-Plane's own aircraft-reference-
# point elevation (sim/flightmodel/position/elevation, what we send as
# elevation_m) sits well above actual ground level for a grounded aircraft
# - roughly 2.4-2.5m for the twins in this project's own bundled Shared
# Cockpit profiles (BE58/BE9L), and the -1.45 auto-detected offset only
# corrected part of that gap.
# -2.5 is a tuned approximation for that same reason a single generic
# placeholder model can never be exactly right for every real aircraft
# type it stands in for (their actual reference-point heights differ) -
# retune this the same way (fly two instances, compare against known
# elevation, adjust) if it's later found off for a materially
# different aircraft type/mix.
VERT_OFFSET -2.5

ICAO GENR
