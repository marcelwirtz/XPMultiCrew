# Shared Cockpit "systems" dataref list for the default X-Plane 12 Cessna
# 172SP (ICAO type "C172") - see shared_cockpit/shared_cockpit_config.h's
# ResolveSharedCockpitConfigPath: this file is picked up automatically
# whenever the current aircraft's ICAO type matches this filename, no
# ROLE/PEER needed here (those come from the companion app - see the root
# README's Phase 3 section).
#
# Every dataref below was checked against a real X-Plane 12
# Resources/plugins/DataRefs.txt, not guessed, and all are the "writable"
# (y) kind. Deliberately NOT included: anything X-Plane only accepts
# writes to via an override flag (e.g. sim/cockpit2/autopilot/heading_mode
# needs sim/operation/override/override_autopilot engaged first) - mirroring
# those blindly wouldn't stick, since X-Plane's own autopilot logic would
# just overwrite them back next frame. Autopilot *mode engagement* (HDG/NAV/
# ALT button state) is therefore out of scope for now; the bugs/targets
# below (heading/altitude/vspeed/airspeed dial) work fine since those are
# plain pilot-set values, not autopilot-owned state.
#
# Also note: flap position and the four exterior lights are NOT already
# covered by the automatic position/attitude sync (that packet's
# flap_ratio/light_bits fields are only used to draw OTHER pilots' aircraft
# in Formation mode - shared_cockpit_sync.h's ApplyMasterPoseToOwnAircraft
# only ever touches position/heading/pitch/roll on your own aircraft), so
# they're listed here explicitly too.
#
# Every DATAREF line below also carries a CATEGORY tag (engine/avionics/
# systems - "systems" is the default, so it's only spelled out here for
# clarity). MASTER and CLIENT can each own a category's datarefs
# independently, swapped via the companion app's ownership buttons - a
# locally-detected change to a dataref whose category this side doesn't
# own gets reverted instead of applied/broadcast, which is what actually
# fixes a hardware switch fighting the network instead of just narrowing
# the window it can happen in (see shared_cockpit/ownership_tracker.h).
# MASTER owns every category by default when a session starts.

# Engine / fuel / start procedure
#
# throttle_ratio_all and ignition_key were missing/undersynced here and
# were the actual cause of a live-tested bug: the master's running engine
# didn't show as running on the client, and the client couldn't start it
# either.
#   - throttle_ratio_all: simply wasn't in this list at all, so the two
#     sides' independent engine physics had no way to agree once either
#     pilot moved the throttle.
#   - ignition_key's own X-Plane doc string says it's "spring-loaded for
#     starter - you have to keep setting it to start in order to keep
#     cranking." DatarefSync only broadcasts on value *change* by default,
#     so the receiving side got exactly one "start" write instead of a
#     sustained crank signal. STREAM makes DatarefSync resend it every
#     tick regardless of change, like AircraftPosition already is.
# ENGN_running is force-synced too, as a belt-and-suspenders measure so the
# client's engine visually/audibly matches the master even if the
# reconstructed start sequence doesn't perfectly reproduce X-Plane's
# internal start timing.
DATAREF sim/cockpit2/engine/actuators/throttle_ratio_all CATEGORY engine
DATAREF sim/cockpit2/engine/actuators/mixture_ratio_all CATEGORY engine
DATAREF sim/cockpit2/engine/actuators/carb_heat_ratio CATEGORY engine
DATAREF sim/cockpit2/engine/actuators/primer_on CATEGORY engine
DATAREF sim/cockpit2/engine/actuators/ignition_key STREAM CATEGORY engine
DATAREF sim/cockpit/engine/fuel_pump_on CATEGORY engine
DATAREF sim/cockpit/engine/fuel_tank_selector CATEGORY engine
DATAREF sim/flightmodel/engine/ENGN_running CATEGORY engine
